# Security

Do not place credentials, unredacted diagnostics, real disk labels or personal file paths in public issues. Use synthetic reproductions and describe the affected version and operation.

If GitHub private vulnerability reporting is enabled, use the repository's Security tab. If it is unavailable, open a minimal issue asking for a private reporting channel without including sensitive details.

The app does not require an API key. Signing certificates, private keys and provisioning profiles must remain outside the repository.
